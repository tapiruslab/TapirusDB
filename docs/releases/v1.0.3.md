# TapirusDB v1.0.3

This patch release brings post-v1.0.2 source changes into a versioned build.
The GitHub release assets and the package registries must each be verified
before their availability or compatibility is claimed.

## Changes

- The HTTP server binds to loopback by default and requires an API key for a
  non-loopback bind. Request headers, bodies, read time and simultaneous clients
  are bounded; review the server documentation for exact limits.
- The TAP model loader rejects oversized serialized models, inconsistent
  dimensions and non-finite weights. Default TAP weights remain deterministic
  heuristics, not trained or probability-calibrated predictions.
- The Rust browser workspace includes TAP Lite inference. Browser snapshots
  remain unencrypted; use a native SDK for encrypted local files.
- The unified TAP guide and package status documentation clarify supported APIs,
  installation paths and the distinction between current source and published
  packages.
- The dependency advisory report records production and development-only
  findings separately. Development-only findings remain visible for review.
- The HTTP client limit uses an atomic compare-and-exchange loop compatible
  with the declared Rust 1.85 minimum and newer strict Clippy toolchains.

## Release checks

Pre-tag CI for the versioned candidate commit `1448e3e` passed all jobs in
[run 42638007361](https://github.com/tapiruslab/TapirusDB/actions/runs/42638007361).
This is candidate source evidence only. The tag-triggered release workflow must finish,
package checksums must match downloaded artifacts, and Rust, Python and Node.js
registry publications require separate confirmation.

TapirusDB supports a documented SQL subset and selected vector, graph and JSON
APIs. This release does not imply full SQL or openCypher conformance, a general
latency guarantee, a security certification or a managed service SLA.
