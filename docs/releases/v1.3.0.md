# TapirusDB v1.3.0

`v1.3.0` delivers the Edge-to-Cloud Synchronization, Disk-Backed `IVF-EMEANS` Vector Indexing, SIMD Bloom Filter Multi-Join Optimizer, Browser OPFS 4KB Pager, and Multi-Thread Session Hardening release line.

## Changes in v1.3.0

- **Disk-Backed `IVF-EMEANS` Vector Index (`TPIVFE01`) & Fast E-Means Clustering (`src/vector/ivf.rs`):** Upgraded `IvfIndex::train_and_build` from 8-pass batch k-means to 2.5-epoch mini-batch Exponential Moving Average (**E-Means**) clustering (`train_emeans_centroids`) with half-cosine learning-rate annealing and proportional dead-cluster revival, and added `DiskBackedIvfEmeansIndex` (`TPIVFE01`) with on-disk contiguous cluster posting pages, per-cluster `CRC32` verification, optional `RaBitQ` RAM codes, and real-time `hot_buffer` delta mutations.
- **Cost-Based Multi-Join Reordering & 512-Bit 8-Lane SIMD Block Bloom Filter Pushdown (`src/sql/executor/`):** Added `plan_cbo_inner_join_order` to reorder multi-table `INNER JOIN` chains by selectivity while respecting table dependencies, alongside cache-line-aligned `SimdJoinBloomFilter` (`[u64; 8]`) probe pushdown to reject non-matching left rows in L1 cache before probing hash tables.
- **`TapirSync` (`TPSYNC01`) Edge-to-Cloud Replication Protocol (`src/tapirsync.rs`):** Implemented the 38-byte binary-framed `TPSYNC01` multi-modal delta replication protocol with hardware `CRC32` integrity, `TapirSyncCursor` incremental tracking, and Hybrid Logical Clock Last-Write-Wins (`TapirSyncHlc`) conflict resolution across relational tables, JSON documents, property graph vertices/edges, and AI Agent Memories.
- **Browser OPFS Zero-Copy 4KB Pager (`src/pager/remote.rs` & `crates/tapirus-wasm/src/lib.rs`):** Added `OpfsSyncPager` (`RemoteRangeReader` + `RemoteStorageAdapter` with a bounded 4 KiB LRU page table and dirty-page tracker) and `#[wasm_bindgen] TapirusWasm::from_opfs_pager` so multi-GB `.tapir` vaults stream and decrypt (`ChaCha20-Poly1305`) 4 KiB B+Tree and HNSW pages on demand.
- **HNSW RNG Neighbor Pruning & Multi-Thread Session Ergonomics (`src/vector/hnsw.rs`, `src/session.rs`):** Added `diverse_neighbors_slices` to eliminate redundant `HashMap` lookups during HNSW graph construction (`1.45x` faster index build) and introduced `SessionDatabase::session_blocking()` with `DEFAULT_BUSY_TIMEOUT` (`5s`, matching SQLite `PRAGMA busy_timeout`).
- **Native FFI Wheel & N-API Binary Matrix Verification (`scripts/verify-sdk-binary-matrix.py`):** Added automated CI verification for Python `abi3` wheels (`.pyd`/`.so`) and Node.js N-API (`.node`) PE/ELF/Mach-O headers across all 5 release targets.

## Release checks

Source validation passes before tagging `v1.3.0`, including workspace formatting, strict Clippy (`-D warnings`), Rust core + edition profiles + `fault-injection` recovery + `tapirus-micro`, WASM (`@tapirus/wasm` and `@tapirus/wasm-lite`), TLA+ TLC2 crash-safety checks, OSV dependency advisory checks, and `scripts/check-release-version.py --tag v1.3.0`.

The tag-triggered release workflow (`release.yml`), crates.io publication (`tapirus`, `tapirus-micro`, `tapirus-ffi`, `tapirus-wasm`), PyPI (`tapirus`), Packagist (`tapiruslab/tapirusdb`), and npm (`tapirus`, `@tapirus/wasm`, `@tapirus/wasm-lite`) are synchronized at version `1.3.0`.

TapirusDB supports a documented SQL subset and selected vector, graph and JSON APIs. This release does not imply full SQL or openCypher conformance, a general latency guarantee, a security certification or a managed service SLA.
