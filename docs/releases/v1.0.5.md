# TapirusDB v1.0.5

This patch release strengthens AI Memory multi-tenant isolation, adds external neural embedding support to `tapirus mcp`, exposes namespace-scoped `/api/memory/*` HTTP endpoints on `tapirus serve`, and tunes default HNSW and RRF retrieval parameters for higher top-K recall and paraphrase accuracy.

## Changes

- Added `MemoryAccessScope` and `Connection::scoped_memory(namespace, session_id)` (plus `Error::PermissionDenied`) to enforce hard per-owner namespace and session boundaries across document writes, searches, gets, counts, links, forgets, prunes, expired purges, deletions, and `memory_request_json`.
- Upgraded `tapirus mcp` with `--embed-endpoint`, `--embed-model`, `--embed-dims`, `--embed-api-key`, `--namespace`, and `--session-id` (and corresponding `TAPIRUS_EMBED_*` / `TAPIRUS_MCP_*` environment variables), supporting caller-supplied dense embeddings and Ollama (`/api/embed`, `/api/embeddings`) / OpenAI-compatible (`/v1/embeddings`) HTTP neural endpoints alongside explicit `deterministic-hash-fallback` status reporting and `__sys_memory` SQL protection when scoped.
- Added `POST /api/memory`, `/api/memory/store`, `/api/memory/search`, and `/api/memory/forget` to `tapirus serve` alongside repeatable `--api-key-namespace <KEY>=<NS>` / `TAPIRUS_API_KEY_NAMESPACES` bindings that restrict tenant keys strictly to their isolated namespace on `/api/memory*`.
- Tuned `MemoryConfig::default()` (`ef_construction = 128`, `ef_search = 512`) and `MemorySearch::default()` (`rrf_k = 20.0`, `vector_weight = 0.65`, `lexical_weight = 0.25`, `recency_weight = 0.05`, `importance_weight = 0.05`) to widen the default HNSW traversal beam and prevent noisy BM25 distractors from outranking semantic paraphrase matches.

## Release checks

Source validation must pass after all release candidate changes before tagging `v1.0.5`.
The tag-triggered release workflow (`release.yml`), crates.io publication (`tapirus`,
`tapirus-micro`, `tapirus-ffi`, `tapirus-wasm`), PyPI (`tapirus`), and npm (`tapirus`,
`@tapirus/wasm`) publications are synchronized at version `1.0.5`.

TapirusDB supports a documented SQL subset and selected vector, graph and JSON
APIs. This release does not imply full SQL or openCypher conformance, a general
latency guarantee, a security certification or a managed service SLA.
