# TapirusDB v1.0.4

This patch release hardens key material handling and HTTP server defaults, switches AI Memory storage to compact binary records with persisted HNSW index snapshots, expands the C FFI (`tapirus-ffi`), and synchronizes all native and WASM package registries.

## Changes

- `DatabaseCipher` no longer implements `Clone`, and scrubs raw key, salt, and epoch material on drop via `zeroize`; intermediate HMAC/PBKDF2 derivation buffers are also zeroized after key derivation.
- `tapirus serve` disables wildcard `Access-Control-Allow-Origin: *` by default (opt in selectively with `--cors-origin` or `TAPIRUS_CORS_ORIGIN`) and documents placing plaintext HTTP behind a TLS-terminating reverse proxy.
- AI Memory storage (`__sys_memory`) now writes a compact bounds-checked binary format (`TPMEM001`) while preserving backward-compatible reads of legacy JSON records, and persists validated HNSW index snapshots (`__sys_memory_index`) so database reopen restores indexed vector recall without full rebuilds.
- Expanded `tapirus-ffi` with `tapirus_execute_params`, `tapirus_query_params_json`, AI Memory C ABI functions (`tapirus_memory_request_json`, `tapirus_store_memory_json`, `tapirus_search_memories_json`, `tapirus_forget_memory`), `sqlite3_bind_*` (`null`, `int`, `int64`, `double`, `text`, `blob`, `clear_bindings`, `bind_parameter_count`), `sqlite3_column_blob`, and deferred `sqlite3_step` execution for bound statements.
- Fixed a B+Tree interior cell left-child pointer update and leaf cell deduplication edge case when non-rightmost leaf pages split during updates.
- Added `@tapirus/wasm` packaging and npm publication jobs to `.github/workflows/publish-sdks.yml`.

## Release checks

Source validation must pass after all release candidate changes before tagging `v1.0.4`.
The tag-triggered release workflow (`release.yml`), crates.io publication (`tapirus`,
`tapirus-micro`, `tapirus-ffi`, `tapirus-wasm`), PyPI (`tapirus`), and npm (`tapirus`,
`@tapirus/wasm`) publications are synchronized at version `1.0.4`.

TapirusDB supports a documented SQL subset and selected vector, graph and JSON
APIs. This release does not imply full SQL or openCypher conformance, a general
latency guarantee, a security certification or a managed service SLA.
